# Backup Script

Скрипт для создания резервных копий (архивов) указанной директории с логированием и механизмом повторных попыток при сбоях.

## Описание

Скрипт предназначен для автоматического создания архивов. Он решает две задачи:

- **Надежность**: если архивация не удалась с первого раза (например, из-за временной блокировки файла или нехватки места), скрипт делает до 5 попыток.
- **Логирование**: весь вывод (как успешный, так и ошибки) перенаправляется в лог-файл, что делает скрипт идеальным для запуска по расписанию (через cron или systemd timers), когда нет возможности наблюдать за ним в терминале.

## Настройка

Перед первым запуском откройте скрипт и измените две переменные в начале файла на свои значения:

```bash
LOG_DIR="/путь/куда/складывать/логи/и/архивы"
SRC_DIR="/путь/к/папке/которую/нужно/архивировать"
```

- `LOG_DIR` — директория, где будут храниться файл `backup.log` и созданные архивы.
- `SRC_DIR` — директория, содержимое которой будет упаковано в архив.

## Использование

Сделайте скрипт исполняемым и запустите его:

```bash
chmod +x backup.sh
./backup.sh
```

### Запуск через Cron

Скрипт спроектирован так, чтобы его можно было безопасно запускать из cron (он не зависит от текущей рабочей директории и перенаправляет весь вывод в лог). Пример записи в crontab для ежедневного запуска в 3 часа ночи:

```
0 3 * * * /path/to/backup.sh
```

## Как это работает (Архитектура)

1. **Перенаправление вывода**: В начале скрипта используется перенаправление потоков. Это означает, что весь текст, который генерирует скрипт (и стандартный вывод, и ошибки), будет дописываться в конец лог-файла.

2. **Цикл повторных попыток**: Функция `back()` использует цикл `while` с ограничением в 5 итераций (`count -lt 5`). Если команда `tar` завершается с ошибкой (возвращает ненулевой код выхода), счетчик увеличивается, и цикл запускает попытку заново.

3. **Успех**: Как только архив успешно создан, функция выводит сообщение и делает `return 0`, немедленно завершая работу функции.

4. **Провал**: Если все 5 попыток провалились, скрипт выводит сообщение об ошибке и завершает работу с кодом 1 (что сигнализирует системе, что задача завершилась неудачно).

## Пример лога

При успешном выполнении в файле `backup.log` появится запись, похожая на эту:

```
[27-10-2026 14:30:00] Backup успешно создан!
```

Если архивация упадет, лог покажет причину (например, `Permission denied` от `tar`), а затем сообщения о попытках:

```
tar: /path/to/src: Cannot open: Permission denied
[27-10-2026 14:30:00] Не удалось создать backup! Попытка 1. Пробую ещё раз...
```
